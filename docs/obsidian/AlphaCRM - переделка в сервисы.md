# AlphaCRM - переделка в сервисы

> [!summary] Суть
> Разделить текущий монолит AlphaCRM на связанные сервисы, расширить роли и добавить склад, полноценную кассу, корпоративный диск и персональный дашборд сотрудника.

Карта: [[AlphaCRM]] · Метрики: [[AlphaCRM - метрики и графики]]  
Код (если vault = `docs`): [[architecture]], [[data-model]], [[target-architecture]]

## 1. Сервисы

### 1.1 Финансы / Касса → [[AlphaCRM - сервис Финансы]]
- Проведение финансовых операций
- Выставление счетов и их оплата
- Аналитика покупок и продаж → [[AlphaCRM - метрики и графики]]
- Связь со счётами на приёмы/услуги, **без** утечки клинического текста

### 1.2 Склад → [[AlphaCRM - сервис Склад]]
- Накладные на препараты и расходники
- Категории номенклатуры (пример: «медпрепарат») + сортировка/фильтрация
- Интеграция с [[#5. Честный знак|Честным знаком]] (см. ниже)

### 1.3 База данных (пациенты / клиника) → [[AlphaCRM - сервис Клиническая БД]]
- Карточки пациентов, медданные, документы приёма
- Жёсткая изоляция: [[Роль Техподдержка]] **не** видит данные из этой БД

### 1.4 Дашборды / расписание → [[AlphaCRM - сервис Расписание]]
- Расписание, записи, прайс услуг, аналитика посещаемости
- **Приветственная страница сотрудника** — открывается первой после входа
  - персональная аналитика → [[AlphaCRM - метрики и графики]]
  - быстрые действия по роли
- Новый врач → создан аккаунт → появляется в расписании

### 1.5 Диск → [[AlphaCRM - сервис Диск]]
- Общий диск наподобие Google Drive
- Загрузка документов, шаринг доступа
- Отдельно от медицинских PDF пациента (корпоративные файлы клиники)

### 1.6 (идея) Навигационный ассистент → [[AlphaCRM - сервис Ассистент]]
- LLM **не вносит данные** и не ходит в БД сама
- По запросу («новая карточка пациента») **открывает пустую форму** — действие делает пользователь
- Только белый список UI-команд + RBAC роли
- Assistive navigation, не autonomous agent

## 2. Роли и возможности

> [!important] Правило
> UI только прячет кнопки. Решение о доступе — всегда на сервере.

| Роль | Код (черновик) | Возможности |
|---|---|---|
| [[Роль Администратор\|Администратор]] | `ADMINISTRATOR` | Всё в клинике, **кроме зарплат** других сотрудников |
| [[Роль Старший администратор\|Старший администратор]] | `SENIOR_ADMINISTRATOR` | Как администратор + создание отчётов |
| [[Роль Врач\|Врач]] | `DOCTOR` | Мед. БД, расписание, документы, прайс **только чтение** |
| [[Роль Менеджер\|Менеджер]] | `MANAGER` | Операционный контур + графики; создание сущностей (врач → аккаунт → расписание) |
| [[Роль Медперсонал\|Мед. персонал]] | `NURSE` / `MEDICAL_STAFF` | Склад, БД пациентов, расписание |
| [[Роль Техподдержка\|Техподдержка]] | `SUPPORT` | Всё **кроме** данных из медицинской/пациентской БД |
| [[Роль Владелец\|Владелец]] | `OWNER` | Всё + опасная операция **удаления БД** (только свой тенант, подтверждение, аудит) |

Открытый вопрос: судьба текущей роли `CASHIER` — оставить отдельно или влить в права администратора/финансов.

## 3. Свободный прайс

- Позиции каталога со **свободной ценой** (не фиксирована / вводится при записи или оплате)
- Включает/назначает **администратор** (и выше по матрице)
- Врач видит прайс, **не меняет**
- Нужны правила: кто задаёт сумму, валидации до оплаты, как попадает в finance-аналитику

---

## 4. Склад — детали

1. Накладные (приход / расход / списание / перемещение — уточнить минимум)
2. Категории + сортировка (медпрепарат и др.)
3. Честный знак — см. следующий раздел

Списание при приёме — через события/команды, **не** прямой доступ к чужой БД.

---

## 5. Честный знак

Продумать:

- что хранить локально (GTIN, SGTIN/КИЗ, статусы);
- какие операции требуют обмена с ГИС МТ / True API;
- MVP без живой интеграции: порт + mock + очередь исходящих;
- границы: склад = остатки и марки, касса = деньги, clinical = пациенты.

> [!warning]
> Проект не заявляет соответствие регуляторике. Интеграцию сверять с официальной документацией и юристом.

## 6. Касса / финансы — детали

- Выставлять счета и принимать оплату
- Вести аналитику покупок и продаж для менеджерских графиков
- Идемпотентность оплат
- Онлайн-касса / фискализация — за портом (как сейчас `FiscalPort`)

---

## 7. Нефункциональные требования

- Multi-clinic: везде `clinicId`
- Аудит без клинического текста в reason
- Событийная связь сервисов (outbox), без shared domain DB
- Миграция без big bang: порядок в монолите → вынос по одному
- Первая страница SPA — персональный дашборд
